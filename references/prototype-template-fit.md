# 原型模具适配闸门

用于 `PUI Contract` 和项目独立 `UIP-` 已建立后、任何低保真或中保真原型生成前。目标是选出语义和结构真正适用的模具，并显式说明不匹配项；不能用最近项目、视觉相似或同一业务名称替代检查。

## 1. 强制流程

```text
PUI Contract + ProjectUIProfile
  → 从 Template Catalog 取得允许范围内的候选
  → 逐项比较七个维度
  → 检查硬阻塞项
  → 输出 TFD- 决策
  → exact / extensible / no_match
```

七个维度固定为：目标用户、核心任务、页面类型、信息层级、关键区域、设备尺寸、交互状态。每个维度必须记录 `matched / extensible / mismatched / unknown` 和依据，不能只给总分。

## 2. 硬阻塞项

出现任一情况时不得判为完全匹配或可扩展匹配：

- 核心任务或页面唯一主操作冲突；
- 目标设备、方向、输入方式或最小视口不兼容；
- 模具缺少 P0 信息承载区或必需区域；
- 页面类型会改变入口、出口或核心流程；
- 关键权限、失败、恢复或领域状态无法通过既有扩展点表达；
- 复用需要带入被当前 Profile 禁止的文案、资产、数据或业务规则；
- 候选模具已停用、作用域不允许或版本不可用。

未知的硬阻塞维度必须得到证据或保持 `no_match / blocked`，不能按常识放行。

## 3. 三类结果

| 结果 | 判定 | 后续动作 |
|---|---|---|
| `exact` 完全匹配 | 七维全部匹配；无需改变主任务、P0、骨架、主操作和关键状态 | 创建当前项目实例，清空所有示例内容和资产 |
| `extensible` 可扩展匹配 | 硬阻塞项全部通过；差异只需新增已允许的插槽、可选区域、变体或状态表达 | 记录扩展清单，生成项目实例，不修改原共享模具 |
| `no_match` 无匹配 | 存在硬阻塞、关键维度未知，或扩展会改变主任务/P0/核心骨架 | 不套用旧模具，读取 [项目级候选模具](prototype-candidate-generation.md) 和 [素材占位 Contract](prototype-asset-slots.md) |

“可扩展”不允许通过隐藏 P0、移动唯一主操作、改写业务文案或删除异常出口来制造兼容。

## 4. TFD 决策

输出使用 [`../schemas/template-fit-decision.yaml`](../schemas/template-fit-decision.yaml)，至少包含：

- 当前 `project_id`、`profile_id`、`PUI-` 与 Profile 版本；
- 被比较的候选模具和版本；
- 七维逐项结果、证据和不匹配原因；
- 最终结果、选中模具或 `no_match`；
- 可扩展项、禁止继承项、待确认项和下一动作；
- 决策状态与 Owner。

只在 Profile、PUI、模具版本和七维结论均可追溯时标记 `ready`。任一输入变化后，旧 `TFD-` 标为 `superseded` 并重新检查。

## 5. 用户可见摘要

进入原型前首行固定为 `TFD-ID｜exact/extensible/no_match｜ready/blocked`，再简要说明采用哪个模具、为什么命中、有哪些不匹配或扩展、哪些旧内容不会继承。若 `no_match`，明确说明将创建当前项目专属黑白候选模具，不要求用户理解 Catalog、Schema 或 Registry。

## 6. 验收

- 每次原型生成都能回指一个 `ready` 的 `TFD-`；
- 结果只使用 `exact / extensible / no_match`；
- 七维均有逐项结论和证据，不以总分替代；
- 硬阻塞项不会被视觉相似、业务同名或历史复用绕过；
- `extensible` 不修改共享模具，只生成项目实例和扩展记录；
- `no_match` 不渲染旧模具或未登记组件。
