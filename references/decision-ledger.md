# 决策账本与变更影响追踪

用于长对话、多次确认、范围调整和跨 Skill 交付。目标是让每条关键规则有唯一状态，并让修改可以传播到功能、页面、组件、状态机、测试与交付产物。

## 1. 何时启用

满足任一条件时维护决策账本：

- 已出现 2 条及以上会影响范围、流程、权限、状态或验收的确认；
- 用户使用“确认、是的、改成、去掉、都要、暂不做”等短回复；
- 用户修改此前已经确认的内容；
- 即将进入设计、研发、测试或跨 Skill 交付；
- 多人评审需要区分提出、确认和执行责任。

账本是内部权威状态。普通对话只展示本轮新增或变化的条目，不要每轮把整张表重复给用户。

## 2. 决策状态

| 状态 | 含义 |
|---|---|
| Proposed | 候选建议，尚未获得用户确认 |
| Pending | 已提出问题，等待明确答复 |
| Confirmed | 用户明确确认，允许进入需求基线 |
| Superseded | 被后续决策替代，保留历史但不再生效 |
| Rejected | 用户明确否决，不进入当前范围 |
| Deferred | 有意推迟到后续版本，不阻塞当前范围 |

只有 Confirmed 决策可以作为下游产物的既定业务规则。Proposed、Pending 和 Deferred 必须继续携带证据标签。

## 3. 决策条目

稳定编号使用 `DEC-001`、`DEC-002`。编号创建后不复用、不因排序变化而改变。

| 字段 | 要求 |
|---|---|
| 决策 ID | 稳定且唯一 |
| 主题 | 一句话说明决策对象 |
| 决策内容 | 可验证、无歧义的当前规则 |
| 状态 | Proposed / Pending / Confirmed / Superseded / Rejected / Deferred |
| 证据 | 用户原话、资料位置或明确的分析依据 |
| 决策人 | 有权确认该规则的角色；未知时标记待确认 |
| 生效版本 | MVP、具体版本或待定 |
| 影响范围 | 目标、对象、流程、功能、页面、组件、状态机、测试、风险、交付物 |
| 替代关系 | 被哪条决策替代，或替代了哪条决策 |
| 更新时间 | 使用对话时间或版本时间，避免伪造精确业务时间 |

## 4. 短回复绑定规则

- “确认 / 是的 / 可以”只能绑定到上一轮唯一且明确的 Pending 决策。
- 上一轮同时存在两个独立问题、多个并列规则或代词指向不唯一时，不得把短回复批量确认；先用一句话指出歧义，只追问具体指向。
- “都要 / 三项都做”可以确认当前明确列出的集合，但必须回写集合内容，不能只记录“都要”。
- “按上面逻辑 / 沿用现有规则”必须记录被引用的对象和规则版本；无法定位时保持 Pending。
- 用户给出新规则时，先判断它是新增、替代还是范围移动，再更新状态；不重置未受影响决策。

示例：

```markdown
已确认 DEC-014：15 秒只限制邀请响应，不限制双方准备。
影响：邀请状态机与 IN-006 测试更新；组队房间继续使用独立的准备等待规则。
```

## 5. 变更事件

每次修改 Confirmed 决策时创建 `CHG-001` 形式的变更事件。

| 字段 | 要求 |
|---|---|
| 变更 ID | 稳定且唯一 |
| 来源 | 用户原话、评审结论或缺陷证据 |
| 变更前 | 原决策 ID 与原规则 |
| 变更后 | 新决策 ID/新规则或移出范围 |
| 变更类型 | 新增 / 修改 / 删除 / 延后 / 恢复 |
| 影响分析 | 逐项检查目标、对象、流程、功能、页面、组件、状态机、测试、风险、发布计划 |
| 更新状态 | Not Started / Updating / Verified / Blocked |
| 验证证据 | 更新后的文档、原型、测试或评审记录 |

修改既有规则时，原 DEC 标为 Superseded，新规则使用新的 DEC ID；不要覆盖历史原文。

## 6. 影响传播

按以下顺序更新，直到所有受影响项均为 Verified：

```text
决策
→ 业务对象与流程
→ 功能与验收标准
→ 页面与组件
→ 状态机与测试
→ 研发任务与发布风险
→ 跨 Skill 产物
```

如果无法判断某层是否受影响，标记 `待评估`，不能默认“无影响”。高影响变更在传播完成前将相关交付状态退回 Needs Decision 或 Blocked。

## 7. 最小展示格式

对话中只展示本轮变化：

```markdown
### 本轮决策变化
| ID | 状态 | 结论 | 影响 |
|---|---|---|---|
| DEC-014 | Confirmed | 15 秒仅用于邀请响应 | 邀请状态机、超时提示、IN-006 |

### 下一项待确认
只保留一个当前最影响方案的问题。
```

终态 PRD、生产交接或跨 Skill Manifest 中，应附当前有效决策快照和未完成的变更影响项。
