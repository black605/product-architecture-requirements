# v0.3 结构原型交接与回传规范

当用户在需求 Ready 后希望先验证“页面是否看得懂、主任务是否走得通”，但尚未确认视觉系统、真实内容或工程实现时使用。目标是降低路径与状态规则的确认成本，不是交付高保真设计或生产代码。

## 1. 启动门槛

- 已明确目标用户、核心任务、主要终端和至少一条主路径。
- 已确认会影响页面可达性的规则，例如顺序、解锁、完成、登录、保存进度、权限或异常恢复。
- 未确认的高影响规则仍保持为 DEC 待确认；不得用原型文案或样例交互把它们静默定案。

缺少上述任一项时，先追问一个阻塞缺口，不生成看似完整的页面。

## 2. 最小交接内容

| 字段 | 说明 |
|---|---|
| Prototype ID | 例如 `PRO-001`，与本轮需求版本绑定 |
| 目标 | 要验证的用户理解或任务路径，而非“做一个页面” |
| 页面范围 | 页面清单、入口、出口、目标设备/视口 |
| 已确认规则 | DEC 原文或稳定 ID，特别标出顺序、锁定、完成和恢复规则 |
| 必须状态 | 正常、进行中、锁定、空/下载/加载、失败或完成中的适用项 |
| 可用假设 | 低风险样例内容、默认排版和可替换视觉处理 |
| 禁止推断 | 角色权限、收费、内容策略、数据来源、算法口径等未确认规则 |
| 验证任务 | 学员或评审者应能完成的动作及成功判据 |

## 3. 原型边界

- 用低保真布局表达信息层级、操作优先级、页面关系和状态差异；视觉品牌、插画、动效和工程组件仅在用户明确要求后继续。
- 样例文案只用于说明结构，必须能替换，不得被表述为真实内容、真实数据或已接入服务。
- 本地模拟下载、网络、进度或跨设备恢复时，应明确为 Mock；只有接入真实服务并验证后才能升级其证据状态。
- 页面须保留返回/继续/恢复入口；锁定状态要说明解锁条件，完成状态要说明后续去向。

## 4. 回传审计

原型生成后至少检查：

1. 主路径可从入口走到结果，且关键操作确有反馈；
2. 锁定、进行中、断网/失败、完成等适用状态均有可理解的文案和去向；
3. 未确认规则没有被页面或测试数据固化；
4. 页面可通过本地 HTTP 预览打开，脚本/控制台无阻断错误；
5. 回传产物路径、验证结果、Mock 边界、未决 DEC 和下一轮建议。

真实用户测试尚未发生时，只能交付测试任务与记录方式，不能把内部走查写成“学员已验证”。
