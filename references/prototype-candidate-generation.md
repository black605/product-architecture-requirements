# 无匹配时的项目级候选模具

当 `TFD-` 结果为 `no_match` 时使用。目标是在不套用旧模具的前提下，依据当前项目 PUI、UIP 和素材 Slot 生成可评审的黑白候选骨架。

## 1. 输入门槛

- `PUI-` 已明确页面主任务、信息/操作层级、区域和关键状态；
- 当前项目 `UIP-` 已记录用户、任务、页面、设备和继承边界；
- `TFD-` 为状态 `ready` 的 `no_match`，且不匹配原因可追溯；
- 影响布局的素材已建立 `ASC-` 或明确 `not_applicable`；
- 会改变主任务、P0、权限或完成口径的 L3 决策已经确认或保持 Blocked。

## 2. 生成流程

```text
PUI 页面骨架
  → 目标设备通用网格
  → P0 区域与唯一主操作
  → P1/P2 区域及坍缩规则
  → 语义组件与素材 Slot
  → 正常态及关键风险态
  → prototype-neutral 黑白表达
  → PTC- 项目候选
```

使用当前项目字段和 `example-only` 样例；不得读取最近原型的文案、素材或布局实例作为隐式默认。可以引用已验证的通用网格、基础可访问性规则和中性组件语义，但每项引用必须记录来源。

## 3. 候选模具约束

- `scope` 固定为 `project-local`；
- `status` 初始为 `draft`，完成结构审计后才可为 `ready-for-prototype`；
- 每个区域和组件回指 PUI、功能、状态或素材 Slot；
- 不包含品牌色、最终字体、插画、图标、动画风格和生产代码；
- 不以占位文案确认未决业务规则；
- 不直接写入共享模板目录或 A2UI Registry。

候选结构使用 [`../schemas/prototype-candidate.yaml`](../schemas/prototype-candidate.yaml)。

## 4. 状态覆盖

候选至少表达正常态和页面最相关的三类风险态；从 loading、empty、error、no_permission、disabled、partial_data、extreme_content、断网/恢复及领域状态中选择。每个状态都有用户出口，不能只更换占位文案。

## 5. 进入原型条件

只有以下条件都满足时，`PTC-` 才能标记 `ready-for-prototype`：

- P0、唯一主操作、入口和出口完整；
- 目标设备与视口下区域不冲突；
- ASC 占位不会遮挡或替代 P0；
- 必需状态和恢复路径可表达；
- 旧项目内容与资产扫描为空；
- PUI、UIP、TFD、ASC、页面和功能追溯完整。

## 6. 验证与后续

候选生成只证明结构可评审。进入 S5 后分别记录技术、目标用户和交接证据；验证通过后才可提交模板登记，未验证前不得称为公共模具或可复用资产。
