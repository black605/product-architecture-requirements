# 防御性 UI Contract

本规范用于把页面或组件的需求输入交付给 A2UI Design Intake、Reverse Engineer 或实现团队。它定义可观察行为，不绑定具体 CSS、框架或渲染器。

## 1. Contract 最小结构

| 字段 | 说明 |
|---|---|
| `contract_id` | 稳定编号，如 `UIC-001` |
| `function_ids` | 对应功能 ID，禁止孤立视觉组件 |
| `component` / `variant` | 组件语义和变体，不直接假设实现文件 |
| `slots` | P0/P1/P2 Slot、内容来源、可见条件与坍缩规则 |
| `states` | 正常、加载、空、失败、无权限及适用业务状态 |
| `content_bounds` | 标题、描述、数值、图片、动作的长度或边界约束 |
| `stress_cases` | 可重复的极端输入和预期表现 |
| `accessibility` | 焦点、可读名称、状态播报、非颜色提示和降级 |
| `acceptance` | Given/When/Then 的可观察验收 |

## 2. Slot 优先级与坍缩

| 级别 | 典型 Slot | 缺失时 | 不变量 |
|---|---|---|---|
| P0 | 主状态、核心对象名、主 CTA、阻塞说明 | 显示明确空/错误/阻塞，不得渲染成功态 | 主任务仍可理解，主操作不被挤出 |
| P1 | 辅助描述、进度、次操作、时间信息 | 用简短说明或稳定占位替代 | 不改变 P0 层级和布局骨架 |
| P2 | 徽章、积分、装饰图、补充标签 | 整个 Slot 自动坍缩 | 不保留空白、不产生无效分隔线 |

不能根据单个字段是否为空判断业务成功。例如订单状态、学习完成、支付结果、评分结果必须由已确认业务状态决定。

## 3. 内容与布局边界

每个可展示文本/数值/资产至少明确以下适用项：

- 长文本：标题可显示的最大行数、超长后的截断或展开入口、不可截断的关键信息。
- 空值：隐藏、占位、禁用、请求补充或展示失败说明的选择与理由。
- 极值：零、负值、满值、非常大数字、异常日期/时区、超多标签或缺失图片。
- 操作保护：主 CTA 在小屏/长文本下仍可见；重复点击、加载中和失败后有明确反馈。
- 视觉可读性：状态不能只靠颜色；图标/关键操作在拥挤内容下保持可识别；动效可降级。

## 4. 状态与压力矩阵

| 状态/输入 | 页面或组件必须表现 | 验收示例 |
|---|---|---|
| 正常 | P0/P1/P2 按优先级出现 | 给定完整数据，主任务、对象和 CTA 可在首屏识别 |
| 加载 | 保持内容骨架或明确进度，不错误展示旧成功结果 | 给定请求未完成，不出现可执行的虚假成功 CTA |
| 空 | 解释为什么为空并提供下一步或边界说明 | 给定无可用内容，用户知道是否可刷新、创建或返回 |
| 失败 | 表示失败范围、恢复入口与保留状态 | 给定请求失败，用户可重试或安全退出，P0 不丢失 |
| 无权限 | 解释资格/权限边界，不泄露受限内容 | 给定无资格用户，只显示允许的摘要与申请/返回入口 |
| 超长 | 文本/标签/数字不覆盖主状态或主 CTA | 给定 80 字标题，主操作仍可见且信息不重叠 |
| P2 全空 | 附加区域完全坍缩 | 给定全部 P2 缺失，页面无多余占位和断裂分隔线 |

## 5. 压力用例包

每个 Contract 至少列出 3 个适用压力用例，并包含输入、预期、关联 Slot、功能 ID 和是否应自动化。例：

| 用例 | 输入 | 预期 | 关联 |
|---|---|---|---|
| ST-01 | 80 字标题 + 3 个长标签 | 主 CTA 可见；标题遵守行数约束；标签不遮挡 | `title(P0)`、`tags(P2)`、F-01 |
| ST-02 | 全部 P2 空值 | P2 区域和分隔线一并坍缩 | `badge(P2)`、F-01 |
| ST-03 | 请求超时 | 显示失败范围与重试；不清空已确认 P0 信息 | `feedback(P0)`、F-01 |

## 6. Handoff 与验收

交付时将 Contract 放入 Handoff Manifest，明确哪些规则是已确认、L1/L2 默认或 L3 待确认。A2UI 下游返回的 Schema、Catalog、Renderer 或视觉 QA 结果必须回填 `contract_id` 和压力用例结果；任何未覆盖的 P0 状态都保持 Blocked，不用截图代替验收。
