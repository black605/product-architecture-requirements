# 非专业用户快速上手

## 用户只说一句想法时

先回复三件事：

1. 用一句话复述你理解的产品目标。
2. 说出你将先帮他梳理什么，不要求他懂术语。
3. 默认只问一个最关键问题，用自然语言和一个回答示例引导，并说明可以随时修改。

示例：

> 我理解你想让老师更快完成作业批改，并让学生及时看到反馈。我们先不讨论技术和页面，先确认真实工作过程。
>
> 我想先确认老师最费时的环节，因为它决定第一版优先做什么。老师从收到作业到给出反馈的过程中，哪一步最花时间？
>
> 例如，可能是“对应学生和作业”“逐份批改标注”或“汇总成绩和写评语”。你也可以直接描述自己的情况，之后随时修改。

## 术语翻译表

| 术语 | 给非专业用户的说法 |
|---|---|
| 用户角色 | 谁会使用这个产品 |
| 权限 | 谁可以做什么，谁不能做什么 |
| 业务流程 | 一件事情从开始到结束怎么完成 |
| 状态 | 事情现在进行到哪一步 |
| 信息架构 IA | 页面和菜单怎么分层 |
| MVP | 第一版必须先做什么 |
| 组件 | 页面里可重复使用的功能块 |
| 验收标准 | 做到什么程度才算完成 |
| ProjectSnapshot | 当前项目唯一有效的结论、问题和交付状态 |
| DEC / CHG | 已确认决策 / 对已确认内容的变更记录 |

## 什么时候进入下一阶段

项目按“输入归集、需求收拢、产品架构、规格生成、中保真线稿、方案验证、生产交付、运营复盘”推进。每阶段只要满足当前 Ready Gate 即可，不要求一次补齐所有细节。

缺失但不影响当前决策的内容标为“待确认”或显式假设；会改变角色、范围、主流程、完成/解锁、权限、收费、数据语义或验收口径的内容必须先确认。原型、测试或运营数据发现新问题时，会更新 DEC/CHG 并退回受影响阶段，而不是重新开始整份需求。

## 需要生成原型时

直接说明目标页面、设备和希望验证的任务，也可以提供 Figma、截图或旧页面。Skill 会为当前项目建立独立 Profile，先说明选中的模具、匹配结果和不匹配项；如果没有合适模具，会生成项目级黑白候选，不会套用旧项目文案和视觉资产。

原型生成后可以直接说“把这个区块移到前面”“增加图片占位”“错误时增加重试”。可逆修改会记录为 Patch；如果修改改变权限、完成条件、算法或主流程，Skill 会先回到需求确认，不会只改页面。
