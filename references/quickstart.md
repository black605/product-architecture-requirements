# 非专业用户快速上手

## 用户只说一句想法时

先回复三件事：

1. 用一句话复述你理解的产品目标。
2. 说出你将先帮他梳理什么，不要求他懂术语。
3. 只问两个最关键问题，并给一个回答示例。

示例：

> 我理解你想让老师更快完成作业批改，并让学生及时看到反馈。我们先不讨论技术和页面，先确认真实工作过程。
> 1. 老师现在从收到作业到完成反馈，最费时间的是哪一步？例如“逐份批改”“汇总成绩”或“写评语”。
> 2. 学生看到结果后，是否需要重交或继续练习？

## 术语翻译表

| 术语 | 给非专业用户的说法 |
|---|---|
| 用户角色 | 谁会使用这个产品 |
| 权限 | 谁可以做什么，谁不能做什么 |
| 业务流程 | 一件事情从开始到结束怎么完成 |
| 状态 | 事情现在进行到哪一步 |
| 信息架构 IA | 页面和菜单怎么分层 |
| MVP | 第一版必须先做什么 |
| 组件 | 页面里可重复使用的功能块 |
| 验收标准 | 做到什么程度才算完成 |

## 什么时候进入下一阶段

每阶段只要用户能回答当前关键问题即可，不要求一次补齐所有细节。缺失但不影响当前决策的内容标为“待确认”；会改变功能边界、权限、成本或页面结构的内容必须先确认。
