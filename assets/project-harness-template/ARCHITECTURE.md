# 架构说明

## 项目目标

补充本项目的产品目标、核心任务、模块边界和依赖方向。没有确认的内容标记为待确认，不用实现细节替代业务决策。

## 模块边界

| 层 | 位置 | 职责 | 不负责 |
| --- | --- | --- | --- |
| 产品需求 | `docs/product-specs/` | 目标、角色、流程、范围、功能和验收 | 直接决定技术实现 |
| 设计决策 | `docs/decisions/` | 记录高影响取舍、来源和影响 | 覆盖历史决策 |
| 实施计划 | `docs/plans/` | 任务、依赖、进度和风险 | 作为第二份需求真相 |
| 质量验证 | `scripts/verify`、`docs/quality.md` | 统一验证、证据和已知缺口 | 替代真实用户测试 |
| 应用代码 | 项目源码目录 | 实现已确认的需求和架构边界 | 静默新增业务规则 |

## 依赖方向

```text
需求/决策 → 架构边界 → 实现 → 自动验证 → 交接与复盘
```

- 实现应回指需求、决策或验收标准。
- 发现需求变化时先回写需求和决策，再改实现与测试。
- 验证失败时优先定位 Contract、实现、测试或环境中的具体缺口，不整体重写掩盖根因。
