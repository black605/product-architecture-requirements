# AGENTS.md

## 项目定位

这是 `{{PROJECT_NAME}}` 的项目级协作规则。项目目标、范围、约束、验收标准和当前阶段必须以仓库文件为准，不依赖聊天记忆。

项目地图见 [ARCHITECTURE.md](ARCHITECTURE.md)，质量规则见 [docs/quality.md](docs/quality.md)。

## Harness Engineering 协作规则

在设计或实现任务期间，Agent 应主动：

- 检查目标、范围、约束和验收标准是否明确；
- 识别缺失的文档、工具、测试、可观测性和安全边界；
- 对非关键缺口采用明确假设并继续；
- 对高风险或不可逆决策请求人工确认；
- 将反复出现的问题转化为可执行约束；
- 在完成任务前运行项目验证，并提供结果证据；
- 提醒代码、架构、需求和文档之间的漂移。

## 项目状态规则

- 需求和决策写入 `docs/product-specs/` 与 `docs/decisions/`；实施过程写入 `docs/plans/`。
- 有 ProjectSnapshot 时，它是需求、架构、原型、测试和交接状态的唯一事实源。
- 新项目或新模块不得默认继承旧项目文案、用户数据、视觉资产、品牌 Token 或业务规则。
- 重复缺陷应沉淀为 Schema、测试、验证脚本或明确约束，而不是只增加提示词。

## 安全边界

- 默认只修改本地仓库；外部推送、发布、登记、部署和生产写入必须得到明确授权。
- 不把静态检查、Mock、截图或本地预览描述成真实用户验证、生产接入或上线完成。
