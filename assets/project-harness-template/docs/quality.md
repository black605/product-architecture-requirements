# 质量规则

## 完成任务前必须检查

1. 目标、范围、约束和验收标准明确；
2. 需求、架构、实现、测试和文档没有已知漂移；
3. 自动验证通过，失败项有记录；
4. 高风险决策已确认；
5. 汇报实际命令、结果和未验证边界。

统一入口：

```bash
./scripts/verify
```

## 证据边界

- 静态检查或文件存在只能证明结构基础。
- 自动化测试只能证明覆盖到的技术行为。
- Mock、截图和本地预览不能替代真实用户验证或生产验证。
- 外部写入、推送、发布、部署和登记必须有明确授权与返回证据。

## 项目专属验证

初始化后，请在 `scripts/verify` 中接入本项目的测试命令，或设置 `PROJECT_VERIFY_COMMAND`。没有项目专属验证时，统一入口会明确输出警告，不会伪装成完整质量通过。
