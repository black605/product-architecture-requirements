# Harness Engineering 配置计划

## 目标

将跨任务协作从聊天记忆升级为项目内可读取、可执行、可验证的工程约束。

## 本次范围

- 增加根目录 `AGENTS.md`，固化协作规则、状态持久化、安全边界和统一工作方式。
- 增加 `ARCHITECTURE.md`，固化模块职责、依赖方向和状态所有权。
- 增加 `docs/product-specs/`、`docs/plans/`、`docs/decisions/` 和 `docs/quality.md`。
- 增加 `scripts/verify`，统一调用 Skill 结构校验、生命周期回归、模具回归、隔离扫描和 Harness 行为回归。
- 在 `SKILL.md` 和 `README.md` 中接入项目治理文件的读取与验证规则。

## 验收标准

- 新任务进入本仓库时可以发现项目地图、质量规则和当前计划。
- 需求、架构、实现、测试和文档之间的漂移有明确提醒入口。
- 统一验证入口能返回可复现的通过/失败证据。
- 不改变既有低摩擦对话、项目隔离、模具适配和原型 Harness 语义。
- 本次配置不自动执行 GitHub 推送、模板登记或生产部署。

## 状态

本计划在配置提交后标记为 `completed`；后续真实项目失败应追加新的决策、计划和回归用例，而不是直接扩大本文件。
