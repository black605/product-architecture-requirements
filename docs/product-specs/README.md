# 产品需求基线

本目录保存当前 Skill 作为“产品”的需求基线与能力边界。具体协议仍以 `SKILL.md` 和 `references/` 为准，避免形成第二份互相冲突的 PRD。

## 当前产品目标

让产品经理、业务专家、教师、设计师、运营和研发协作方通过低摩擦对话，把模糊想法沉淀为：

- 可确认的业务目标、角色、流程、范围和状态；
- 可追溯的功能矩阵、信息架构、页面与组件规格；
- 不继承旧项目语义和资产的项目级中保真原型；
- 可运行、可验证、可回流的 Harness 产物；
- 面向设计、研发、测试和运营的交接包。

## 产品边界

- 核心产物是需求与产品架构规格，不是生产后端、Figma 源文件或已上线系统。
- 原型用于验证信息、任务、状态和页面结构；视觉资产只做位置、比例和状态占位。
- 技术验证、目标用户验证和生产交接证据必须分开记录。
- 外部写入、推送、发布、部署和模板登记不因文档生成而自动发生。

## 需求来源

需求变化应回写 `ProjectSnapshot`，并在高影响场景下创建 `DEC/CHG`。本目录只保留产品级目标和边界；项目实例需求放在各自项目的 `docs/product-specs/` 中。
