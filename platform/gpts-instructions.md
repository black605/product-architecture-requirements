# GPTs 配置

## Instructions

将上级目录的 `SKILL.md` 全文粘贴到 GPTs 的 Instructions 字段。将 `references/meta-prompt.md` 作为维护者的专项评审提示词，不放入终端用户运行指令。

## 推荐 Conversation Starters

- 我有一个模糊的产品想法，请每轮只用 1 个关键问题帮我澄清。
- 请用自然语言提问并允许我直接补充或修改，不需要点击选项。
- 请把这个业务拆成功能矩阵、页面层级和组件规格。
- 请把需求推进到 v0.4 中保真交互线稿，并给出技术、用户和交接验证计划。
- 进入原型前请先建立当前项目 Profile，并说明模具是 exact、extensible 还是 no_match。
- 请在当前对话中生成黑白原型；先展示页面和模具摘要，之后接受自然语言修改。
- 请先生成 Frame/Flow Contract，再用 Harness 检查 1280×800 布局、任务路径和视觉基线。
- 请把访谈或上线指标写回 ProjectSnapshot，形成下一轮 DEC/CHG 和路线图动作。
- 请用 A/B/C 对抗用例评审当前需求，指出最致命的缺陷。
- 需求确认后，请生成高保真原型、研发清单、测试用例与状态机的交接包。

## 能力开关

- 需要最新行业案例或开源项目时开启联网能力，并要求输出来源。
- 需求分析本身不需要代码解释器或图像生成能力；只有用户明确要求专业产物、需求达到 Ready 且 GPT 已配置对应 Action/能力时，才按 Handoff Manifest 调用，并在返回后审计。
- 不使用 Markdown 复选框或字母选项作为默认回退；探索阶段只用一个自然语言问题和示例引导，接受“不要小班，改为录播”等自然语言修改。
- 多次确认或回改时保留稳定 DEC/CHG；短回复只绑定唯一待决项。
- 多人、异步、倒计时、并发、撤回、权限变化或恢复场景自动生成状态转移与测试门槛。
- 需求、原型、验证、交接与运营复盘共享 ProjectSnapshot，不允许并行维护互相冲突的 PRD 状态。
- 每个新项目使用独立 ProjectUIProfile；旧项目文案、用户数据、视觉资产、品牌 Token 和业务规则默认不继承。
- 原型前必须生成 TemplateFitDecision；no_match 时使用项目级候选和素材 Slot。自然语言修改形成带基线的 Patch，L3 变化退回 DEC/CHG。
- 项目边界先判定 resume/fork/new/needs_confirmation；可运行原型必须有 Frame/Flow 与真实 Harness 证据，技术通过不能替代目标用户验证。
- 未配置下游能力时只输出交接包；发布、部署、推送和外部写入不属于默认授权。
