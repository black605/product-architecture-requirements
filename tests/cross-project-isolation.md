# 跨项目 Profile 隔离回归

## 输入

历史项目 A 是面向儿童的学习机横屏口语练习，拥有暖色视觉、课程卡片、人物插画和“开始跟读”文案。新项目 B 是教师桌面端批改工作台。用户要求直接生成 B 的黑白中保真原型，并表示“可以参考以前的页面”。

## 必须行为

1. 为 B 创建新的 `project_id` 与 `UIP-` Profile，不把 A 的 Profile 设为当前权威状态。
2. 把 A 只记录为设计证据来源，分别标记可观察事实、候选继承项和不可继承项。
3. 默认禁止继承 A 的文案、插画、品牌 Token、样例数据、学习业务规则和用户信息。
4. 只有栅格、区域关系、通用组件语义、插槽和状态模式可以进入候选继承集合。
5. Figma 或旧页面不可访问时标记 `inaccessible`，不根据标题补写设计参数。
6. Profile 必须回指 B 的 PUI、页面、功能和 DEC。

## 失败信号

- B 直接使用 “开始跟读”、课程卡片或儿童插画；
- 两个项目共享同一 `profile_id`；
- “参考以前页面”被解释为允许继承全部视觉资产；
- 未读取 Figma 节点却声称已经提取具体栅格或卡片尺寸。
