# 极限测试用例集

每轮优化只选择一个用例。先用当前 Skill 模拟 3–4 轮，再按四维量表评分。

## 用例 A：业务专家/教师，极度模糊输入

**输入：**

> 我想做一个在线评作业的系统，老师能打分，学生能看到，要高级一点。

**检验点：**

- 是否用通俗语言澄清目标、角色、场景、作业生命周期和成功标准。
- 是否在 2 轮内控制问题数量，不把技术术语一次性压给用户。
- 是否继续挖掘提交、批改、退回、重交、反馈和复习闭环。
- 是否明确教师、学生和管理员的权限边界。

## 用例 B：视觉/体验设计师，强 UI 交互诉求

**输入：**

> 我们要重构一个数据大屏和后台控制台，需要支持复杂动效与多视图切换。

**检验点：**

- 是否先确认目标用户、数据刷新方式和核心任务，再进入视觉设计。
- 是否输出栅格布局、视图切换、Tabs、Drawer、Skeleton、Empty、Error 等状态组件。
- 是否给出动效触发、持续时间、降级和无障碍注意事项。
- 是否将视觉建议与未确认业务规则分开。

## 用例 C：产品经理，复杂逻辑与边缘场景

**输入：**

> 做多租户 SaaS 机构分销体系，涉及多级分润与退款撤回。

**检验点：**

- 是否主动澄清租户、机构、渠道、层级、资金池和结算周期。
- 是否推演分润计算、并发、幂等、退款、撤回、冲正、冻结和审计。
- 是否输出权限矩阵、对象状态机、异常流程和验收标准。
- 是否将技术架构标为候选方案，而不是凭空指定实现框架。

## 用例 D：五子棋好友比拼，完整交付回归

**输入：**

> 在现有学习机横屏五子棋中增加“好友比拼”完整闭环，并继续交付高保真原型、研发任务拆分、验收清单、测试用例与状态机。

**检验点：**

- 是否把用户确认的规则写入稳定 DEC 账本，并正确处理“确认/是的”等短回复的唯一指向。
- 是否把好友申请、比拼邀请、组队准备、棋局与消息识别为独立业务对象，而不是只列页面。
- 是否自动触发邀请、组队和棋局状态机，覆盖 15 秒邀请响应、双方准备、5 分钟解散、并发邀请失效与恢复路径。
- 是否保持首期范围：好友互通、加好友、邀请组队、联机对弈、消息中心，以及上线通知、邀请回应和棋局预设文字/表情。
- 是否保持约束：只适配当前学习机横屏、沿用暖色游戏化视觉与真人对弈规则，不做整体视觉重设计。
- 是否在需求 Ready 后生成跨 Skill Handoff Manifest，并对高保真原型、研发清单、测试/状态机三类返回产物做追溯审计。
- 是否验证功能 ID、页面/路由、状态转移、测试 ID 和验收标准之间的链路，不把“文件已生成”当作完成。
- 是否不擅自发布、推送或声称未验证的外部产物已完成。

## 用例 E：产品经理/运营，自然语言确认与回改

**输入：**

> 我们要做一个课程内容运营后台，首期可能要内容发布、活动配置和数据看板，后面还会改优先级。

**第二轮模拟输入：**

> 先选内容发布和活动配置；数据看板暂不做。修改一下，活动配置只做优惠券，不做裂变。

**检验点：**

- 是否以一个自然语言问题确认首期范围，并用例子帮助表达而不要求选择预设项。
- 是否允许用户同时描述多个能力和边界，而不强迫其拆成单选或多选任务。
- 是否在第二轮只更新受影响的选项、流程、功能和验收项，不重置内容发布等既有选择。
- 是否保留“暂定/已确认”状态和“去掉/改成”的自然语言修改入口，同时默认每轮 1 个、最多 2 个决策。
- 是否简短回写变更与影响，不重复要求用户选择或列出完整能力清单。

## 用例 F：教育内容功能迭代（历史项目回归）

**输入：**

> 现在有一个“2026 高考备考专区”，页面上有数学、语文、英语切换，有备考阶段和精选真题卡片。请把它从展示页迭代成真正能帮助学生备考的产品功能。

**检验点：**

- 是否继承当前页面事实，但把用户目标、角色和业务规则标为待确认。
- 是否围绕学科、备考阶段、内容对象和学习记录建立功能矩阵。
- 是否追问卡片点击后的主任务、内容状态、进度和权限，而不是只增加更多卡片。
- 是否区分学生端与内容运营/审核端，并明确未确认的角色边界。
- 是否为阶段导航、内容详情、学习/作答、结果反馈建立状态和验收标准。
- 是否保持 MVP 边界，不凭空承诺题库、推荐算法或在线判分能力。
- 当用户要求组件规范时，是否把基础组件、语义 Token 和学习领域组件分层，并让课程/练习组件回指已确认规则而非静默补全评分、进度或解锁逻辑。
- 是否按目标端路由：教师/运营后台优先 Ant Design + ProComponents，学生端优先 shadcn/ui + Radix；需要严格插槽和复合变体时可选 Park UI + Ark UI + Panda CSS。
- 是否输出 AI 可读取的 `layout_pattern`、`regions`、`slots`、`variants`、`states`、`responsive_rules`、`token_refs` 和 `traces_to`，并把各库保留为候选或已确认的实现基础，避免将原型样式、组件映射或候选技术栈说成已安装的生产能力。

## 用例 G：原型已跑通但缺少目标用户证据

**输入：**

> 我们已经做了一个小学学员跟读原型：课程地图、顺序解锁、独立训练、模拟 AI 纠音、断点续学和自动化回归都通过了。现在能不能直接说它有效并进入 v1.0？真实学员测试结果下周才会有。

**检验点：**

- 是否明确技术回归不能替代目标学员可用性或学习闭环证据，并拒绝将当前状态标记为 v1.0。
- 是否给出紧凑的目标用户任务、独立完成口径、匿名记录和重复风险信号规则，而不是编造测试结论。
- 是否要求每位参与者从相同、可重复的初始状态开始，并说明重置只由主持人执行。
- 是否将测试结果回写到 DEC/CHG、页面/组件、验收与复测任务，而不是只产出一份孤立报告。
- 是否保持 Mock、真实 AI/接口和运营规则的边界，不擅自补全能力。

## 用例 H：原型 UI Contract 语义边界

**输入：**

> 已经确认了学生课后复习页面的功能，先帮我做中保真原型。页面要有课程重点、练习入口、掌握情况和薄弱知识点卡片，视觉先简单清楚，后续再交给设计师做最终视觉。

**检验点：**

- 是否在进入中保真前建立 `PUI-` Contract，而不是直接用视觉稿补齐页面；
- 是否定义页面骨架、唯一主任务、P0/P1/P2 信息层级和主次操作；
- 是否为 Card、练习入口、掌握情况和薄弱知识点建立业务组件语义与字段边界；
- 是否覆盖加载、空、错误、无权限、禁用、部分数据和超长内容等适用状态，并给出下一步出口；
- 是否使用 `prototype-neutral` 作为 `prototype-only` 展示规范，不把蓝色、圆角或阴影当作最终品牌决策；
- 是否输出 `semantic_locked`、`visual_flexible`、`pending_decisions` 和 `forbidden_assumptions`，并禁止下游静默改变权限、算法、完成口径或数据来源；
- 是否保持 Contract、页面、功能、DEC、AC 和验证任务之间的追溯，不把中保真原型文件生成等同于用户验证或生产完成。

## 用例 I：角色化低摩擦对话回归

**输入：**

> 教师：我想做一个收作业和批改的工具，学生交上来我总是对不上人。

**后续输入：**

> 最麻烦是图片作业很多，名字也写得不一样。

**检验点：**

- 是否先用教师听得懂的话复述“作业与学生对不上”的真实问题，而不是用 S 阶段、DEC、Gate 或对象模型开场；
- 是否每轮默认只问一个会影响下一步的问题，并说明为什么问；
- 是否承接“图片作业、姓名不一致”等新增事实，不重复询问已经给出的教师角色和核心痛点；
- 是否把 5W2H 作为内部缺口检查，而不是一次性发给教师填写；
- 是否只有在用户明确要求 PRD、原型、研发/测试交接或版本状态时，才展示内部 ID、状态和追溯信息；
- 是否在用户确认“账号自动匹配为主、老师可手动改”后，用人话回写变化及其影响，不覆盖旧规则或虚构自动识别能力。

## 用例 J：短回复、回改与规格就绪门槛

**输入：**

> 产品经理：先做学生端课后复习，运营后台以后再说。掌握度怎么算还没定，但你先给我完整规格和高保真页面。

**后续输入：**

> 修改一下，整套练习先去掉，改成每个重点后面跟一道小练习，其他范围不变。

**检验点：**

- 探索回复是否控制在约 250 个汉字、无表格，并只提出一个可用一句话回答的决策；
- 是否把“学生端首期、运营后台延期、掌握度待确认”分别承接，不重复询问已知范围；
- 是否因目标用户、预期结果、唯一主任务、首期边界或核心规则不齐而拒绝把 Draft 冒充 `Ready for Specification`；
- 是否只传播“整套练习改为重点后小练习”的影响，不重置未受影响的学生端范围；
- 是否在用户切换到设计/研发交接后改用对应角色语言，同时保持同一份 `confirmed_summary`。

## 用例 K：跨项目模具适配与对话原型

**输入：**

> 参考之前 AI 口语学习机页面，给新的教师批改工作台做一个黑白中保真原型。先在对话里告诉我准备套哪个模具，不合适就生成新的；不要带以前的文案和图片。

**检验点：**

- 是否为新项目建立独立 UIP，并把历史页面只作为证据来源；
- 是否在原型前比较目标用户、核心任务、页面类型、信息层级、关键区域、设备和交互状态；
- 是否输出 exact/extensible/no_match 及逐项依据，而非按视觉相似直接复用；
- no_match 时是否使用通用网格、prototype-neutral、语义组件和 ASC 生成 project-local PTC；
- 是否禁止继承旧文案、用户数据、视觉资产、品牌 Token 和业务规则；
- 是否在同一 PRS 会话中展示生成前摘要、受控 Generation Request、预览状态和自然语言 Patch；
- L3 变化是否创建 DEC/CHG 并退回上游；
- 候选是否经结构、隔离、技术、任务、Owner 和来源证据后才能登记；
- 是否区分模板目录、Runtime Registry、工程消费和生产部署状态。
